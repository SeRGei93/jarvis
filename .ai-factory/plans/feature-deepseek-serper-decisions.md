## Research Context
Source: `.ai-factory/RESEARCH.md` (Active Summary — стек-инварианты) + решения сессии 2026-10-28

- **Goal:** Легковесный стек с одним LLM-балансом (OpenRouter) + внешний Google-поиск с региональностью + быстрые типизированные решения перед агентом; прод = **один контейнер app**.
- **Constraints (инварианты стека):** ESM/NodeNext (`.js` в импортах); инъектируемость (`fetchFn`/`SettingsService`/`ModelFactory`) — тесты без сети; watchdog/timeout на каждый внешний вызов; секреты только в `.env`; `domain/*` чистый (ничего не импортирует).
- **Decisions (зафиксированы с пользователем):**
  - **Чат:** default-роль → `openrouter:deepseek/deepseek-v4.1-flash` (без `:nitro`). Нативный ключ DeepSeek **не заводим** — «встроенный поиск DeepSeek» недоступен через OpenRouter, от него осознанно отказались в пользу Serper.
  - **Поиск:** Serper.dev (Google SERP, `$1/1k`, ключ `SERPER_API_KEY` уже добавлен пользователем в root `.env`). Регион инструмента (`ru-by` дефолт, алиасы) маппится в Google `gl`/`hl` — региональность «по построению», eval-гейт не нужен. SearXNG + redis удаляются целиком (пользователю не нравится, поисковики его блокируют). `fetch_url`, `search_news` и вертикали (avby/kufar/rabota/transport/relax/med103/weather) не зависят от SearXNG — не трогаем.
  - **UI выбора моделей:** отказываемся от реестра `models` (таблица + CRUD-экран + валидация «ref зарегистрирован») — модель выбирается **из живого каталога OpenRouter** (`GET https://openrouter.ai/api/v1/models`, публичный, 464 модели) через backend-прокси с кэшем. Обрезанный каталог ≈ **90 КБ** → отдаём его целиком один раз, а в UI делаем **простой поиск по названию модели** (title, case-insensitive substring) на клиенте — без запросов на каждое нажатие. Роли становятся free-form refs; не-OpenRouter провайдеры (zai/xai/openai/google) вводятся вручную. **Decision-модели в общем каталоге отсутствуют** → отдельный курируемый список (проверено живьём): `typesafe/jev-1.14`, `typesafe/jev-1.13`, `cloudflare/clef-flash`, `cloudflare/clef`, `perplexity/pplx-decider-v1.2`, `perplexity/pplx-decider-v1-27b`, `perplexity/pplx-decider-v1.1-27b` + алиас `~typesafe/jev-latest` (страницы модели нет, в запросах работает). Роль `decision` выбирается из этого списка тем же поиском по названию.
  - **Decision-модели:** Jev, модель-реф **`openrouter:~typesafe/jev-latest`** (псевдоним трекает текущий релиз — выбор пользователя; пороги могут дрейфовать между релизами, принято). Трафик — **через OpenRouter** тем же ключом `OPENROUTER_API_KEY`: провайдер `@ai-sdk/typesafe-ai` (3.x) с `createTypeSafeAi({ apiKey, baseURL: "https://openrouter.ai/api/v1" })` → `.decisionModel("jev-latest")` (OpenRouter экспонирует System One endpoint `POST /api/v1/systemone`). Вызовы — через `Classifier.decide()` из `@mastra/core/classifier` (есть с 1.69, входит в бамп до 1.79); `experimental_decide` из пакета `ai` **не используем** — в нашей `ai@6` его нет (появился в v7). Внимание: `@ai-sdk/typesafe-ai` 3.x собран под provider spec v4 (AI SDK v7) → совместимость с `ai@6` проверяется спайком #1a; при несовместимости — прямой клиент `POST /api/v1/systemone` на `fetch` (план Б, ноль новых зависимостей). Типы вопросов: choice (варианты+вероятности), boolean/noul (P[да]), score (шкала). Оплата только input (~$0.042/M; решение ~$0.00002–0.0001). Обязательный null-фолбэк на существующие LLM-пути (experimental/alpha API).
  - **Кейсы decision-слоя (и только они):** 1) pre-pass роутинг primary-skill (`choice`, criteria = каталог routable-скиллов; argmax; fallback — текущий `generateObject` на `roles.router`); 2) memory dedup (`noul`, порог `p ≥ 0.7` → duplicate; fallback — текущий LLM-путь → fail-open); 3) scope памяти session|permanent (`choice`; fallback — текущий keyword-классификатор, остаётся в `domain` чистым).
  - **НЕ переводим на decision:** `load_skill` агента (агентное многошаговое поведение — модель сама дозагружает скиллы, хоть два за раз), fact/profile extraction (генерация текста), rolling summary, speech.
  - **Mastra:** `@mastra/core` 1.42.0 → **1.79.0** (включая `Classifier` с 1.69), `@mastra/memory` 1.20.3 → **1.39.0**, `@mastra/libsql` → **1.27.0**, + `@ai-sdk/typesafe-ai` **3.x**. **`ai` остаётся 6.x**: Mastra 1.79 мультипровайдерна (внутренние алиасы `provider-v5/v6/v7`) и версию `ai` не форсирует; бампать `ai` до 7 в этом плане не нужно и опасно (переписывание всего LLM-слоя). Актуальные версии npm на 2026-10-28.
- **Open questions:** breaking changes Mastra 1.42→1.79 (выявляются и купируются в Фазе 0 — изолированный коммит, при необходимости откат одного коммита); именование model-id на OpenRouter System One endpoint (`jev-latest` vs `~typesafe/jev-latest` — проверяется живым вызовом в Фазе 4, роль несёт полный реф `openrouter:~typesafe/jev-latest`, маппинг — в decision-модуле); совместимость типов `Classifier` (`DecisionModelV4`, spec v4) с `ai@6` (spec v3) — закрывается спайком #1a, план Б — прямой fetch-клиент.

## Spike #1a — результат (2026-10-28, живой вызов)
- **Транспорт:** `Classifier` из `@mastra/core/classifier` + `@ai-sdk/typesafe-ai@3.0.29` (`createTypeSafeAi({ baseURL: "https://openrouter.ai/api/v1" }).decisionModel(id)`) **типизируется и работает на `ai@6`** без бампа до v7. Прямой systemone-клиент не нужен.
- **Jev недоступен из региона пользователя:** `typesafe/jev-1.14`, `jev-1.13`, `~typesafe/jev-latest` → `HTTP 451 "Typesafe is not available in your region"`. **Решение пользователя: роль `decision` по умолчанию → `openrouter:~perplexity/pplx-decider-latest`** (алиас резолвится в `perplexity/pplx-decider-v1.2-20261016`, ~$0.0000026/решение).
- **Проверено живьём:** `~perplexity/pplx-decider-latest`, `perplexity/pplx-decider-v1.2`, `cloudflare/clef`, `cloudflare/clef-flash` — работают. `perplexity/pplx-decider-v1-27b` и `-v1.1-27b` → 404 (нет endpoints) — из курируемого списка убираем.
- **Семантика ответов:** `boolean`-вопрос уходит на провод как `noul`, SDK возвращает `{type:"boolean", probability}` = **P(да)** (идентичные факты → 0.998, несвязанные → 0.015) — порог dedup `p ≥ 0.7` валиден. `choice` → `{choice, probabilities}`; `score` → `{score, probabilities}`.
- **Важно:** пустой `criteria` у `choice` → upstream 422 → decision-вызов пропускается при пустом каталоге скиллов.

## Риски / заметки
- **Mastra 1.42→1.79** — большой скачок (37 minor): возможны breaking changes Agent/Memory API. Митигация: Фаза 0 изолированным коммитом, откат тривиален. Mastra 1.79 поддерживает `ai` v6 (внутренние алиасы provider-v5/v6/v7), бампать `ai` не нужно.
- **AI SDK spec mismatch** — `@ai-sdk/typesafe-ai` 3.x собран под provider spec v4 (AI SDK v7), проект на `ai@6` (spec v3). Спайк #1a решает: `Classifier` или прямой systemone-клиент. **Бампать `ai` до v7 в этом плане нельзя** — это переписывание всего LLM-слоя.
- **Decision-стек = experimental/alpha поверхности** (System One endpoint OpenRouter, Classifier): все кейсы за null-фолбэком на существующие пути; роль `decision` пустая = фича выключена.
- **`~typesafe/jev-latest` — плавающий псевдоним**: мажорные релизы Jev могут сдвинуть калибровку вероятностей → пересматривать порог dedup (0.7) после заметных релизов; при дрейфе — временно пиннуть конкретную версию в роли через админку (никакого кода).
- **Serper кредиты/лимиты** (2500 free → $50 min top-up): при 401/403/429 инструмент вернёт модели понятную ошибку; `fetch_url`/`search_news`/вертикали продолжают работать. `num` — подсказка, реально ~10 organic/страница; пагинацию не делаем (каждая страница = отдельный кредит).
- **Jev state > ~32КБ** → long-context режим (медленнее/менее точно): в dedup state обрезаем до ~20k символов; роутинговый state компактный по построению.
- **Существующая прод-DB**: сиды не применяются сами — миграция `DROP TABLE models` + выставление ролей в админке (шаг в деплой-заметке #14); модели больше не регистрируются.
- **Каталог OpenRouter** — внешняя зависимость админки: кэш 6ч + `stale`-ответ и ручной ввод ref при недоступности; decision-список статический (офлайн). Алиас `~typesafe/jev-latest` не имеет страницы модели (404 на `/models/{id}/endpoints`), но принимается System One endpoint'ом — в UI помечается как alias.
- **Порядок фаз**: Mastra-бамп + спайк первыми, чтобы фичи писались поверх проверенного API; Фазы 2–3 и 4 независимы друг от друга.
